## 0. What this chunk must achieve

Before this chunk the mod only adds the charter to the system prompt. After it:
1. A prompt the CLIENT types is classified with decideMode. A full-process prompt opens a job; a solo prompt opens nothing and costs nothing extra.
2. While a full-process job has no client sign-off, the model and its subagents cannot change files.
3. Checks the model declares are run under observation; their pass or fail is recorded from the real exit code, never from the model's word.
4. The job cannot reach G8 (delivery) without passing checks and accepted chunks, and the model cannot end its reply claiming completion on an unfinished full job without being sent back once.
5. A logged client override exists so a broken gate can never jam the client's work.

When no full-process job is open, every hook must behave exactly as if the mod were not there (pass through with `next(e)`).

## 1. Pure logic: W/hooks/gate.ts (+ W/hooks/gate.test.ts)

No `$`, no I/O. Export:

- `CLIENT_ORIGINS: readonly string[] = ['composer', 'bridge']` and `isClientOrigin(kind: string | undefined): boolean`.
- `parseClientCommand(text: string): { cmd: 'agree' | 'close' | 'gates-off' | 'gates-on'; arg: string } | null` — the whole message must start (after leading whitespace, case-insensitive) with `!agree`, `!close`, `!gates off` or `!gates on`, followed by whitespace or the end. `arg` is the rest, trimmed. Anything else returns null.
- `isFileChangeTool(tool: string): boolean` — true for `Write`, `Edit`, `NotebookEdit`.
- `isReadOnlyBash(command: string): boolean` — conservative: split the command on `&&`, `||`, `;`, `|` and newlines; EVERY segment must be read-only. A segment is read-only when its first word is one of: ls, cat, head, tail, wc, grep, rg, pwd, echo, which, file, stat, du, df, tree, find, sed, git; and: `find` has none of `-delete`, `-exec`, `-execdir`, `-ok`; `sed` has `-n` and no `-i`; `git` is followed by one of status, log, diff, show, branch, blame, rev-parse, ls-files, remote (and for `branch`/`remote` with no further argument starting with `-d`, `-D`, `-m`, `add`, `remove`, `rm`, `rename`). Anything containing `>` (redirection), `$(`, a backtick, or `<(` is NOT read-only. Empty command is not read-only.
- `wrapCheck(command: string): string` — returns `( <command> ); echo "__COMPANY_EXIT__=$?"`.
- `parseExitMarker(stdout: string): number | null` — the integer from the LAST line matching `__COMPANY_EXIT__=<n>`; null if none.
- `claimsCompletion(text: string): boolean` — true when the text claims the work is finished: whole-word, case-insensitive matches of: done, complete, completed, finished, "all tests pass", "all tests passed", "all checks pass", "all checks passed", "ready for review", "ready to ship", shipped, delivered. A match does NOT count when one of not, isn't, isnt, aren't, arent, no, never, nothing, yet appears within the 3 words before it. Examples that must be false: "not done yet", "this isn't finished", "nothing is complete". Examples that must be true: "Done.", "All tests passed and the feature is complete.", "The job is finished".
- `jobMarker(job: Job | null, gatesOff: boolean): string` — one line: `[company-job id=<id> mode=<mode> gate=<gate> agreed=<yes|no> gates=<on|off>]`, or `[company-job none gates=<on|off>]` when job is null.
- `statusText(job: Job | null, gatesOff: boolean): string` — for the status line: `company: GATES OFF (client override)` when gatesOff; `company: solo · no open job` when no job; otherwise `company: <id> full <gate> · awaiting client sign-off` before agreement, else `company: <id> full <gate> · checks <passing>/<total> · chunks <accepted>/<total>` (latest check per name).

gate.test.ts: table tests for every function, including every refusal listed above.

## 3. Wiring: W/hooks/register.tsx

Keep the existing `session.start` and `prompt.compose` hooks (the charter stays). State lives in `$.state` under the contract keys (read with `$.state.get`, write with `$.state.set`). Add:

### 3a. session.start
Register the tool `job` with `$.tool.register` (model sees `mcp__company__job`; read the `$.tool.register` and `ToolSpec` docs). Description: "Company job record: show status, move the job through gates G1-G8, add chunks with their owner, model and effort, set chunk status with evidence, declare checks. The client's sign-off cannot be given through this tool." Input schema: object with `action` (enum: status, advance, reopen, add_chunk, set_chunk, declare_check) required, and optional `to`, `note`, `chunk` (object: id, title, owner, model, effort), `chunkId`, `status`, `evidence`, `name`, `command`. Then set the status line with `statusText`.

### 3b. prompt.submit
- If `e.origin?.kind` is not a client origin (`isClientOrigin`): return `next(e)` untouched. Never create a job or obey a command from a non-client prompt.
- Client command (`parseClientCommand`):
  - `agree`: if there is an open full job at G4, apply `recordAgreement` and add context "Client signed off on job <id>." Otherwise add context "Client typed !agree but it was not applied: <reason>." 
  - `close`: if a job is open, set its `closedAt` and clear `currentJobId`; add context "Client closed job <id>: <arg>." Otherwise context "No open job to close."
  - `gates-off` / `gates-on`: set `gatesOff`, append to `overrides` `{ at, what: 'gates off' | 'gates on', reason: arg }`, add context stating it.
  In every command case pass the prompt on with `next({ ...e, context: [...(e.context ?? []), note] })` (read the prompt.submit `context` doc) and update the status line.
- Otherwise, if a job is open: pass on with one context line, the `jobMarker`.
- Otherwise: `decideMode({ text: e.text })`. Solo: `next(e)` (rewrite `text` only if a prefix was removed). Full: create job id `J<n>` (n = number of jobs ever created + 1), title = first 60 characters of the text, mode full; set it current; pass on with context: the `jobMarker` plus "This request is in FULL PROCESS under the charter (reasons: <reasons>). Work through G1 Intake, G2 Assessment and questions, G3 Simulation, G4 Client review. You cannot change files until the client types !agree. Use the job tool to move gates." Update the status line.

### 3c. tool.call on the job tool (`{ tool: 'mcp__company__job' }`)
Serve the tool. Every result's text starts with the `jobMarker` line, followed by the outcome, or `REFUSED: <reason>` when jobs.ts refuses. `status` lists gate, agreement, chunks (id, owner, model, effort, status), latest checks, declared checks, overrides, and the last origin kind seen by prompt.submit. `advance`/`reopen` use jobs.ts. `add_chunk` adds with status `todo` and empty evidence. `set_chunk` uses `setChunkStatus`. `declare_check` stores `{ name, command }` (refuse a duplicate name). With no open job every action except `status` is refused with "no open job (solo mode)". No action can set `clientAgreed`. Update the status line after every change.

### 3d. tool.call guard: agreement gate (all tools, main loop and subagents)
If gates are on, a job is open, its mode is full and `clientAgreed` is false: deny `isFileChangeTool` tools, and deny `Bash` unless `isReadOnlyBash(e.command)`. Deny with `{ deny: 'company gate: job <id> is in full process and the client has not signed off (G4). Lay out the plan and wait for the client to type !agree. The client can also type !close or !gates off.' }`. Allow every other tool with `next(e)`. Write it fail-closed with the documented pattern: `on(...).catch(($, e, next) => next.called ? next(e) : { deny: 'company gate error: action refused; the client can type !gates off' })`.

### 3e. tool.call: check observation (Bash)
After the agreement gate allows a Bash call: if a job is open and the trimmed command equals a declared check's command, run it as `next({ ...e, command: wrapCheck(e.command) })`, read stdout from the result (read the Bash result type in the types file), `parseExitMarker`, and `recordCheck({ name, pass: code === 0, at: now, evidence: 'exit=<code or none>; ' + last 300 characters of stdout })`. A missing marker or an interrupted run is a fail. Update the status line. Order the guard and the observer so a denied call is never run.

### 3f. classic.Stop: proof gate (module)
If gates are on, a job is open, it is full, its gate is G7, `claimsCompletion(e.last_assistant_message ?? '')` and `e.stop_hook_active` is not true: return `{ block: 'company proof gate: job <id> is at G7. Completion cannot be claimed until the job reaches G8 through the job tool, which needs every check passing and every chunk accepted. Run the checks, record them, then advance.' }`. Otherwise `next(e)`. This hook is deliberately fail-OPEN (a broken Stop gate must never trap the session); say so in a comment. The shell gate is the second, independent check.

## 4. Second gate: W/hooks/stop-gate.sh and W/hooks/hooks.json

hooks.json becomes: `{ "modules": ["./register.tsx"], "hooks": { "Stop": [ { "hooks": [ { "type": "command", "command": "bash \"${CLAUDE_PLUGIN_ROOT}/hooks/stop-gate.sh\"", "timeout": 10 } ] } ] } }` (quote the placeholder; the validator asks for it).

stop-gate.sh reads the Stop hook JSON from stdin (fields: transcript_path, last_assistant_message, stop_hook_active). It uses python3 when present (`command -v python3`), else exits 0. Logic: find the LAST `[company-job ...]` marker anywhere in the transcript file; if it says mode=full, gate=G7, gates=on, and last_assistant_message claims completion (same rule as claimsCompletion, re-implemented in python), and stop_hook_active is not true, print `{"decision": "block", "reason": "company proof gate (shell): ..."}` and exit 0. In every other case, and on any error, exit 0 with no output (fail-open, same reason as 3f). It must not write any file.
